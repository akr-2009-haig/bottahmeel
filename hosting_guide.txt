هذا الدليل يشرح جميع خيارات الاستضافة المناسبة لبوت تيليغرام مع خطة رفع عملية
تصلح لانطلاقة كبيرة قد تصل إلى 2,000,000 مستخدم عند توزيع الحمل بشكل صحيح،
مع طريقة الإعداد من الهاتف بدون حاجة للابتوب.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📌 المتطلبات الأساسية لهذا البوت:
  • Python 3.11+
  • PostgreSQL 14+
  • RAM: 512 MB كحد أدنى للتجربة فقط
  • CPU: 1 core كحد أدنى للتجربة فقط
  • اتصال إنترنت مستمر (uptime 99%+)

📌 متطلبات الانطلاقة الكبرى الموصى بها:
  • Intake/Webhook: عدد 1 إلى 2 خدمة، لكل خدمة 2 vCPU و 2-4 GB RAM
  • Workers: عدد 4 إلى 8 خدمات كبداية، لكل Worker ‏4 vCPU و 4-8 GB RAM
  • PostgreSQL: 4 vCPU و 8-16 GB RAM مع SSD سريع ونسخ احتياطي تلقائي
  • Redis: 2 vCPU و 4-8 GB RAM
  • Reverse Proxy / Load Balancer: Nginx أو Caddy أو خدمة سحابية مماثلة
  • تخزين: NVMe / SSD فقط
  • نمط التشغيل: Webhook + Redis + Workers متعددين

الإعداد من الهاتف (باستخدام Termius أو JuiceSSH):
  1. أنشئ حساباً على hetzner.com

  3. حمّل تطبيق Termius من متجر التطبيقات
  4. اتصل بالسيرفر عبر SSH (IP + كلمة مرور)
  5. نفّذ الأوامر التالية:
     $ apt update && apt install -y python3 python3-pip git postgresql
     $ git clone https://github.com/YOUR_REPO/YOUR_BOT.git
     $ cd YOUR_BOT
     $ pip3 install -r requirements.txt
     $ nano .env   # أضف TELEGRAM_BOT_TOKEN و DATABASE_URL
     $ python3 run_bot.py &
  6. لتشغيل البوت دائماً استخدم:
     $ apt install -y supervisor
     $ nano /etc/supervisor/conf.d/mybot.conf
     [program:mybot]
     command=python3 /root/YOUR_BOT/run_bot.py
     autostart=true
     autorestart=true
     $ supervisorctl reread && supervisorctl start mybot

🚀 خارطة رفع موصى بها لهذا المستودع حتى 2,000,000 مستخدم:

القاعدة الأهم:
  هذا المشروع لا يصبح مناسباً لملايين المستخدمين بسبب "سيرفر واحد خارق" فقط،
  بل بسبب تقسيم العمل بين:
  - intake / webhook
  - worker processes
  - Redis queue
  - PostgreSQL
  - reverse proxy

البنية الموصى بها للانطلاقة:
  1. خدمة Webhook واحدة على الأقل (ويفضّل 2 عند بدء الحمل الحقيقي)
  2. من 4 إلى 8 Workers كبداية
  3. PostgreSQL مُدار أو على VPS منفصل
  4. Redis مُدار أو على VPS منفصل
  5. Nginx أمام خدمة الـ webhook

خطوات الرفع التفصيلية على Ubuntu Server مع GitHub:
  1. أنشئ VPS أو Cloud VM بنظام Ubuntu 24.04 أو 22.04
  2. افتح المنافذ 80 و443 و22 فقط للعالم الخارجي
  3. ثبّت Docker و Docker Compose Plugin:
     $ sudo apt-get update
     $ sudo apt-get install -y ca-certificates curl gnupg
     $ sudo install -m 0755 -d /etc/apt/keyrings
     $ curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
     $ echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
     $ sudo apt-get update
     $ sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
  4. انسخ المشروع من GitHub:
     $ git clone https://github.com/akr-2009-haig/Karar-bots-downloader.git
     $ cd Karar-bots-downloader
  5. جهّز ملف البيئة:
     $ cp .env.example .env
     ثم عدّل القيم التالية على الأقل:
       - TELEGRAM_BOT_TOKEN
       - BOT_OWNER_ID
       - DATABASE_URL
       - REDIS_URL
       - BOT_MODE=webhook
       - QUEUE_BACKEND=redis
       - WEBHOOK_URL=https://your-domain.example.com
       - WEBHOOK_SECRET_TOKEN=سر_قوي_وعشوائي
  6. شغّل الخدمات:
     $ docker compose up -d --build
  7. زد عدد الـ workers عند الحاجة:
     $ docker compose up -d --scale worker=4
  8. تحقق من الصحة:
     $ curl http://127.0.0.1:8081/healthz
     $ curl http://127.0.0.1:8081/readyz
     $ curl http://127.0.0.1:8081/queuez
  9. اربط Nginx أو Caddy أو Load Balancer أمام المنفذ 8080 مع شهادة TLS
 10. اختبر البوت فعلياً من تيليغرام قبل الإعلان العام
 11. راقب queue depth وعدد العمال والفشل عبر /queuez والسجلات

مثال Nginx مختصر:
  server {
      server_name your-domain.example.com;
      location /telegram/webhook {
          proxy_pass http://127.0.0.1:8080;
          proxy_set_header Host $host;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }
  }

سيرفرات متكاملة مع GitHub لهذا المشروع:
  1. GitHub Actions + Hetzner / DigitalOcean / Contabo / Linode
     - الأنسب للإطلاق الكبير
     - يعطيك تحكماً كاملاً وكلفة أفضل
  2. Railway
     - ربط GitHub مباشر وسهل
     - مناسب للبداية والإطلاق المتوسط
  3. Render
     - ربط GitHub سهل جداً
     - مناسب أكثر حين تريد بساطة الإدارة
  4. Fly.io
     - متكامل جيداً مع GitHub وDocker
     - جيد لتوزيع الـ webhook جغرافياً
  5. Google Cloud Run / AWS App Runner
     - يدعمان مسارات CI/CD مرتبطة بـ GitHub
     - قويان عند الحاجة لتوسع مرن ومدفوع حسب الاستهلاك

كيف تختار؟
  - إذا أردت أعلى تحكم وأفضل سعر: Hetzner أو Contabo مع GitHub Actions
  - إذا أردت أسهل بداية: Railway أو Render
  - إذا أردت Docker + انتشار عالمي: Fly.io
  - إذا أردت بنية سحابية مؤسسية: Google Cloud Run أو AWS App Runner
